# Universal RCC Chimneys — Website Project

## 1. Project Overview

This project is the development of the official website for Universal
RCC Chimneys.

The website is intended to establish a professional digital presence
for the business, communicate its industrial services and project
experience, and generate qualified enquiries from potential customers
across India.

The website must be treated as a real B2B industrial website rather
than as a generic portfolio or template-based business website.

---

# 2. Business Context

Universal RCC Chimneys is associated with RCC chimney construction,
chimney and boiler repair works, refractory works, chimney painting,
and refractory material supply based on the existing company catalogue.

The company intends to serve customers across India.

The business currently has active offices in:

- Gujarat — main/head office
- Vuyyuru, Andhra Pradesh — active office

Exact current addresses and several other business details remain
pending verification.

See:

- `docs/business/company-profile.md`
- `docs/business/services.md`
- `docs/business/verification-status.md`

These documents are the authoritative project references for business
facts.

---

# 3. Primary Project Objective

Build a professional, technically sound, SEO-focused B2B website that
helps potential industrial customers understand the company's
capabilities and contact the company for business enquiries.

The website should accomplish four primary objectives:

1. Establish credibility.
2. Explain genuine services clearly.
3. Demonstrate relevant project experience.
4. Generate qualified leads.

---

# 4. SEO Objective

The business wants the website to appear prominently in Google when
potential customers search for RCC chimney and related industrial
services.

Examples of initial search themes include:

- RCC chimney
- RCC chimneys
- RCC chimney construction
- RCC chimney construction company
- RCC chimney manufacturer
- industrial RCC chimney
- chimney construction
- chimney repair
- refractory works
- refractory material supply

These are initial keyword themes only.

They are NOT validated target keywords.

SEO research must determine:

- Actual search demand
- Search intent
- Geographic intent
- Keyword difficulty/competition
- Commercial intent
- SERP characteristics
- Competitor landscape
- Appropriate landing pages
- Content requirements
- Internal linking opportunities

The project must not use keyword stuffing or create low-quality pages
solely to manipulate rankings.

---

# 5. Important SEO Reality

The business has expressed the desire for the website to rank #1 in
Google for relevant RCC chimney searches.

The project should pursue strong organic search performance, but nobody
can legitimately guarantee a #1 Google ranking.

Therefore:

"Rank #1 on Google"

is a BUSINESS GOAL / ASPIRATION.

It is NOT a technical requirement that can be guaranteed by the
developer.

The website should instead optimize for measurable SEO outcomes such
as:

- Search visibility
- Relevant keyword rankings
- Organic impressions
- Organic clicks
- Qualified organic enquiries
- Search Console performance
- Relevant non-branded traffic
- Conversion rate from organic traffic

# 9. Lead Generation

The website should make it easy for potential customers to contact
the company.

Potential conversion mechanisms include:

- Phone call
- WhatsApp
- Email
- Contact form
- Request a quotation form
- Project enquiry

The exact conversion mechanisms must be determined after understanding

This answer should influence the website's lead-generation design.

---

# 10. Enquiry / Quote Functionality

The initial website should support a straightforward way for a
potential customer to submit an enquiry.

Potential fields:

- Name
- Company
- Phone number
- Email
- Location
- Service required
- Project type
- Approximate project requirements
- Message
- Optional document/photo attachment

The exact fields should be determined based on the company's actual
sales workflow.

Do not collect unnecessary personal information.

submitted.

---

# 11. Backend Requirement

The website should NOT introduce a backend merely because it is a
modern web application.

At the initial planning stage, there is no confirmed requirement for:

- User authentication
- JWT
- Customer accounts
- Admin dashboard
- Complex database
- Custom REST API
- Customer portal

A primarily static/content-driven architecture may be sufficient if the
business only requires informational pages and enquiry mechanisms.

A backend or database should be introduced only when a genuine
functional requirement justifies it.

Possible future backend requirements could include:

- Persistent enquiry management
- Admin dashboard
- CRM integration
- Automated quotation workflow
- File/document management
- Customer accounts
- Analytics/event processing

These are NOT currently confirmed requirements.

# 12. Technical Philosophy

The website should prioritize:

1. Performance
2. Accessibility
3. SEO
4. Security
5. Maintainability
6. Reliability
7. Mobile usability
8. Clear information architecture
9. Fast page delivery
10. Simple architecture where possible

Technology should serve the business requirement.

Do not introduce:

- Databases
- Authentication
- APIs
- Microservices
- Complex state management
- Unnecessary dependencies

unless a documented requirement justifies them.

# 13. Mobile and Responsive Design

The website must be fully responsive.

Primary device categories:

- Mobile phones
- Tablets
- Laptops
- Desktop computers

The mobile experience is particularly important because industrial
customers may discover the company through mobile search or referrals.

---

# 14. Performance Requirements

The website should be engineered for strong real-world performance.

Consider:

- Core Web Vitals
- Image optimization
- Responsive images
- Lazy loading where appropriate
- Font optimization
- Minimal JavaScript
- Code splitting where applicable
- Caching
- CDN delivery
- Efficient hosting
- Minimal third-party scripts

Performance should not be sacrificed for unnecessary visual effects.

---

# 15. Accessibility

The website should follow modern accessibility practices.

Consider:

- Semantic HTML
- Proper heading hierarchy
- Keyboard navigation
- Accessible forms
- Meaningful labels
- Alt text
- Sufficient contrast
- Focus states
- Screen-reader compatibility
- Reduced-motion considerations

Accessibility should be part of implementation rather than a final
afterthought.

---

# 16. Security

Even if the final website is primarily static, security remains
important.

Requirements include:

- HTTPS
- Secure hosting configuration
- No secrets committed to Git
- Environment variables for sensitive configuration
- Input validation
- Spam protection for forms
- Secure handling of uploaded files if attachments are supported
- Dependency security
- Proper HTTP security headers where appropriate

Never commit:

- API keys
- passwords
- authentication tokens
- private credentials
- database passwords
- deployment secrets

# 28. Definition of Success

The project is successful when:

### Business

- Potential customers can clearly understand what the company does.
- Genuine services are clearly presented.
- Credibility is established.
- Customers can easily contact the business.
- Qualified enquiries are generated.

### Technical

- Website is reliable.
- Website is secure.
- Website is responsive.
- Website is accessible.
- Website performs well.

### SEO

- Important pages are crawlable and indexable.
- Search engines understand the website structure.
- Relevant pages rank for appropriate search intents.
- Organic visibility improves over time.
- Organic traffic produces relevant business enquiries.

A #1 ranking is desirable but cannot be guaranteed.
